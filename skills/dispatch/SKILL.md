# Dispatch (Headless Cross-Harness Orchestrator)

Drive `/usr/local/bin/agent-dispatch` directly from this designer session—no manual window-switching or prompt pasting.

## Routing & Realistic Boundary Model
- **Default Worker**: `codex:gpt-6.2-sol@xhigh` (aliases: `codex:sol`, `codex:astra`, `opencode:sol`, `opencode:astra`, `pi:sol`, `pi:astra`, `agy:neon`, `agy:carbon`, `agy:argon`, `agy:hydrogen`).
- **Default Reviewer (auto cross-vendor)**:
  - GPT-family Worker (`codex` / `opencode` / `pi`) -> **`agy:gemini-4-neon-xhigh`** (`--mode plan`, two parallel fresh-context axes: Standards + Spec).
  - Antigravity Worker (`agy`) -> **`codex:gpt-6.2-sol@xhigh`** (`--sandbox read-only`).
- **Defense-in-depth child isolation** (under host root / Full Access):
  - Strips `LINEAR_API_KEY`, `GH_TOKEN`, `GITHUB_TOKEN`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, `SSH_ASKPASS` (and `CODEX_SUB2API_API_KEY` from non-Codex subprocesses); isolates `GH_CONFIG_DIR` to an empty temp dir, uses empty global Git configuration and disables system Git configuration + `GIT_TERMINAL_PROMPT=0`, disables repo hooks and fsmonitor on orchestrator Git calls and external diff drivers for gate and review patches, disables Linear MCP on headless Codex, and sets `AGENT_DISPATCH_CHILD=1` to block nested dispatch.
  - Verifies **SHA-256** integrity of ALL orchestrator-owned artifacts (`brief.md`, `diff-rN.patch`, and every `baseline-standards/*` snapshot) before and after review, checks local `.git/config` + `.gitattributes` + branch/history integrity, verifies worktree `HEAD` + clean status after review, and checks this ticket's remote branch SHA + monotonic `origin/<base>` ancestry + Linear ownership fields (state, assignee, description hash) across worker/verify/review phases.
  - *Boundary transparency*: Because the host runs as `root` with Full Access enabled by user preference (and disk files such as `/etc/environment` remain readable by root), these controls prevent accidental leakage and detect tampering rather than forming an OS-level kernel container boundary. Note also that `codex` (`--sandbox read-only`) and `pi` (`--tools read,grep,find,ls`) enforce tool-level read-only restrictions, whereas `agy` (`--mode plan`) and `opencode` (`--agent plan`) rely on mode discipline (and `agy` shares `~/.gemini/config/mcp_config.json`; pass `--reviewer codex:sol@xhigh` or `--reviewer pi:sol@xhigh` when stricter tool-level read-only isolation is desired).
- **Orchestrator-owned audit artifacts**: Brief snapshots, baseline standards (`git show <base_sha>:...`), `diff-rN.patch`, redacted streaming stdout/stderr logs (individual diagnostic lines over 2 MiB receive an omission marker), `sessions.jsonl`, JSON schemas, and atomic checkpoints live under `~/.cache/agent-dispatch/runs/<repo_key>/<ID>/<run_id>/`. Each harness invocation has a 32 MiB combined stdout/stderr limit. Exceeding it terminates the child and records an error in the session trace. Worktree lock ownership metadata (`owner.json` including `issue_uuid` and `branch`) is persisted inside the repo lock before the worktree becomes visible to `cleanup`/`status`.

## Commands

Run from the target repository root (or pass `--repo /path/to/repo`):

| Intent | Command |
| :--- | :--- |
| Preflight environment, rubrics & repo checks | `agent-dispatch doctor [--project ...]` |
| Run one Linear ticket (one initial attempt, default two rework rounds, configurable from zero to five) | `agent-dispatch run <ID> [--worker ...] [--reviewer ...] [--verify-cmd "..."] [--setup-cmd "..."] [--max-rework 2] [--worker-timeout 1800] [--review-timeout 900] [--fresh] [--force-rerun] [--skip-baseline] [--allow-branch-only]` |
| Reconcile an interrupted claim or publish, or verify completed delivery read-only | `agent-dispatch resume <ID>` |
| Run one conflict-free wave of ready unblocked `Todo` + `agent-ready` tickets | `agent-dispatch frontier [--max-parallel 2] [--limit N] [--worker ...] [--reviewer ...]` |
| Run the current unblocked frontier wave of a Parent Spec | `agent-dispatch spec <PARENT_ID> [--max-parallel 2] [--limit N] [--worker ...] [--reviewer ...]` |
| Standalone heterogeneous review (Standards; add `--issue <ID>` for Spec) | `agent-dispatch review [--base origin/main] [--issue <ID>] [--reviewer ...] [--review-timeout 900]` |
| Show Linear frontier, blocked tickets, locks (`locked`/`unlocked`/`unknown`), and worktrees | `agent-dispatch status` |
| Prune merged, clean, ownership-verified unlocked worktrees (`--all` **force-deletes** unmerged dirty worktrees owned by this repo!) | `agent-dispatch cleanup [--all]` |

Run `agent-dispatch <command> --help` for the full flag list. A batch checks started tickets throughout its Linear project. Local processes sharing the dispatch cache also reserve each selected ticket’s Touches during preflight and execution. Distinct subdirectories can run concurrently. Managed worktree paths are checked for symlinks below the configured cache root. Cleanup checks the branch and its SHA again after the merge lookup and deletes a branch only at the verified SHA. A wildcard reserves the directory before its first wildcard segment. A root wildcard reserves the whole repository. Cleanup can reclaim an interrupted detached baseline when its lock is free and its recorded base and repository still match. After upstream delivery reaches Done, rerun `spec` or `frontier` to select the next wave.


## Safety, Quality Gates & Failure Semantics
1. **Preflight guards (before claiming Linear)**: Publishing requires an origin remote. Preflight verifies the repository matches the ticket's Linear project, fails closed on unrecognized non-GitHub remotes (unless `--allow-branch-only`), scans ticket title for secrets before invoking any model, refuses unpushed/uncommitted `GLOSSARY.md` (including monorepo `**/GLOSSARY.md`)/`docs/adr/` in main repo, checks remote branch fast-forward compatibility, verifies the fetched base tip using its own verification command in a detached worktree when needed, acquires repo path & canonical ticket `flock` locks, persists `claim_pending`, and re-fetches Linear immediately before claiming `In Progress`.
2. **Mandatory verify + granular protected paths + deterministic test check**: An explicit verification command or a repository-wide Make/just target takes precedence. Automatic detection combines the supported language checks in mixed repositories. The baseline cache records the resolved verification command, and the orchestrator detects the command again for every candidate commit, including rework. Bootstrap must leave the checked-out branch, HEAD, index and tracked files intact before the ticket can be claimed. Setup-generated helper paths stay excluded from each candidate commit, including rework. Cleanup preserves helpers whose identity or contents changed. A missing verify command or ambiguous mixed Python pytest/unittest suites (without `pytest` installed) or JS repos with tests but only `lint` fail closed (`--allow-no-verify` to opt out). Unapproved edits to protected gate/policy files (cross-depth `Makefile`/`justfile`/`pyproject.toml`/`pytest.ini`/`ruff.toml`/`Cargo.toml`/`.cargo/*`/`vite.config.*`/`playwright.config.*`/`mypy.ini`/`.coveragerc`/`conftest.py`/`GLOSSARY.md`/`.gitattributes`/`*.mk`/`docs/adr/*`/`.github/workflows/*`/`.github/actions/*`/`package.json` gate sections) or test deletions/skips trigger rework. Ticket-brief exemptions are **fail-closed**, segment-glob scoped (single `*` never crosses `/`), ignore fenced code blocks, and accept ONLY `- gate: <path/glob>` or `- test: <path/glob>` lines under `## Authorized Gate/Test Changes` (or explicit `--allow-gate-edits` / `--allow-test-edits`). Gate file lists use NUL-delimited Git output.
3. **Full-range secret scan + SHA-locked two-axis review**: Scans ticket/PR titles, filenames, commit messages, and additions throughout `base_sha..candidate_sha`, including merge and binary changes before verify/review, locks `candidate_sha`, checks each model attempt’s input artifacts against their recorded SHA-256 hashes, redacts deleted secret lines in `diff-rN.patch` (blocking added secrets in standalone `review` before any LLM runs), runs parallel Standards ([references/review-standards.md](references/review-standards.md)) and Spec ([references/review-spec.md](references/review-spec.md)) reviews (auto-retrying once on JSON parse / timeout / transient error), and validates strict JSON schemas.
4. **Honest state machine & human-state ownership**:
   - **Pre-publish failures** (`worker_blocked`, `failed_max_rework`, unhandled error) can stash safe, uncommitted worktree edits for reruns. Sensitive edits stay in place for inspection. These failure paths preserve human-set states (never overwriting `Done`/`Canceled` or manually moved tickets), and otherwise add `dispatch:failed` **first** before reverting to the pre-claim state + redacted diagnostics with session traces.
   - **Interrupted claim.** `resume` compares the pending claim with live Linear state, assignee and description. A safely released claim reports `claim_released`. Start the implementation again with `run`. An older pending checkpoint with insufficient ownership evidence requires human reconciliation.
   - **Interrupted publish.** `resume` checks the reviewed SHA, destination, PR identity and Linear ownership. The live base branch must still contain the base tip fetched in preflight. Older checkpoints use the recorded merge base. A legacy publish checkpoint needs a verifiable destination before it can write. Its historical GitHub repository identity can supply that evidence. Relative local origins resolve from the source repository. A push uses the observed branch SHA as a lease after checking ancestry. Once the push is confirmed, moving or deleting the remote branch stops reconciliation. The orchestrator records the identity of any existing Draft PR before implementation. Closing that PR stops publication. A compatible Draft PR keeps its title and body. At `pr_ready` and `linear_state_synced` the remaining operations synchronize Linear and deduplicate the delivery comment. A completed checkpoint receives read-only verification. SIGINT, SIGTERM and SIGHUP preserve the recoverable stage, with failure registration attempted during cleanup.
   - **`--no-push` local mode** writes to `latest-local.json` (never clobbering `latest.json`) and does not mutate Linear state or comments.

## Designer Handling Rules
- Full runs can take 10–60+ minutes; run via `run_command` with `NotificationTimeoutSeconds: 600` (inspect live streaming logs in `<run_dir>/*.log` and `<run_dir>/sessions.jsonl` if still running; do not poll in a loop).
- Present a crisp summary table on completion: **Ticket | Status | Commit / Draft PR | Worker / Reviewer | Verify | Standards | Spec | Side Issues**.
- Always include a **Session Traces** block listing every headless session in `sessions`: render `agy` sessions as clickable `[<role>](conversation://<conversation_id>)` links, show `codex resume <id>` / `opencode -s <id>` / `pi --session <path>` commands, and link `<run_dir>` via `file://`.
- **Failure routing**:
  - `worker_blocked` -> clarify the blocker with the user, update Linear, rerun `/dispatch <ID>`.
  - `failed_max_rework` -> inspect `<run_dir>` logs; run **`/diagnose`** for subtle bugs or **`/slice`** if the ticket was too large.
  - `publish_incomplete` -> resolve the reported ownership, remote or connectivity issue and run **`agent-dispatch resume <ID>`**.
  - `base_branch_red` -> fix the base branch first.
- If `discovered_issues` is non-empty, list them and ask whether to create follow-up Linear tickets.
- For interactive TDD or manual review inside this session, consult [references/tdd.md](references/tdd.md), [references/review-standards.md](references/review-standards.md), or [references/review-spec.md](references/review-spec.md), and follow [references/review-convergence.md](references/review-convergence.md) for manual dual-agent audit rounds (threat-model boundary, 2-round funnel, complexity breaker, and convergent review prompt template).
